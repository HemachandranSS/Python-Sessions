HAS-A Composition

Using members of one class inside another class by creating an object.

  • Also called Composition
  • Create object of one class inside another
  • Main advantage: Code Reusability
  • When you want to use existing functionality

IS-A Inheritance

Child class inherits from parent class automatically.

  • Also called Inheritance
  • Child class extends parent class
  • Main advantage: Code Reusability
  • When you want to extend existing functionality

HAS-A Relationship (Composition)

Demo 1: Car HAS-A Engine

A Car class that contains an Engine object.

class Engine:
  a = 10
  def __init__(self):
    self.b = 20
  def m1(self):
    print('Engine Specific Functionality')

class Car:
  def __init__(self):
    self.engine = Engine() # HAS-A Relationship
  def m2(self):
    print('Car using Engine Class Functionality')
    print(self.engine.a)
    print(self.engine.b)
    self.engine.m1()

c = Car()
c.m2()
Car using Engine Class Functionality

20
Engine Specific Functionality
Code Reusability

The Car class reuses Engine's functionality without modifying Engine class. This is the main advantage of HAS-A relationship.

Demo 2: Employee HAS-A Car

An Employee class that contains a Car object.

class Car:
  def __init__(self, name, model, color):
    self.name = name
    self.model = model
    self.color = color
  def getinfo(self):
    print("Car Name:{} , Model:{} and Color:{}".format(self.name, self.model, self.color))

class Employee:
  def __init__(self, ename, eno, car):
    self.ename = ename
    self.eno = eno
    self.car = car # HAS-A Relationship
  def empinfo(self):
    print("Employee Name:", self.ename)
    print("Employee Number:", self.eno)
    print("Employee Car Info:")
    self.car.getinfo()

c = Car("Innova", "2.5V", "Grey")
e = Employee('Hema', 10000, c) # Pass Car object
e.empinfo()

HAS-A Relationship

In this program, Employee class HAS-A Car reference and hence Employee class can access all members of Car class.

IS-A Relationship (Inheritance)

What is Inheritance?

Whatever variables, methods, and constructors are available in the parent class are by default available to the child classes. We don't need to rewrite them.

Main Advantages of Inheritance

1. Code Reusability - Reuse parent class code

2. Extend Existing Functionality - Add new features to child class

# Syntax: class childclass(parentclass)
class Parent:
  # Parent class members...

class Child(Parent): # Child inherits from Parent
  # Child class members...

Demo 1: Basic Inheritance Example

Child class inherits all types of methods from Parent class.

class P: # Parent class
  a = 10
  def __init__(self):
    self.b = 10
  def m1(self):
    print('Parent instance method')
  @classmethod
  def m2(cls):
    print('Parent class method')
  @staticmethod
  def m3():
    print('Parent static method')

class C(P): # Child class inherits from Parent
  pass # Empty child class

c = C()
print(c.a)
print(c.b)
c.m1()
c.m2()
c.m3()
10
10
Parent instance method
Parent class method
Parent static method
Code Reusability Example

If Parent class has 10 methods and Child class has 5 methods, then Child class actually has 15 methods (10 inherited + 5 own). We don't need to rewrite parent class methods!

Demo 2: Parent & Child Methods

Child class can have its own methods in addition to inherited ones.

class P: # Parent class
  a = 10
  def __init__(self):
    self.b = 20

class C(P): # Child class
  c = 30
  def __init__(self):
    super().__init__() # Call parent constructor
    self.d = 40

c1 = C()
print(c1.a, c1.b, c1.c, c1.d)
10 20 30 40
Important Note

If we don't call super().__init__() in the child constructor, the parent's instance variables (like b) won't be available to the child class.

Demo 3: Employee IS-A Person

Real-world example: Employee inherits from Person.

class Person:
  def __init__(self, name, age):
    self.name = name
    self.age = age
  def eatndrink(self):
    print('Eat Biryani and Drink Beer')

class Employee(Person): # Employee IS-A Person
  def __init__(self, name, age, eno, esal):
    super().__init__(name, age)
    self.eno = eno
    self.esal = esal
  def work(self):
    print("Coding Python is very easy just like drinking Chilled Beer")
  def empinfo(self):
    print("Employee Name:", self.name)
    print("Employee Age:", self.age)
    print("Employee Number:", self.eno)
    print("Employee Salary:", self.esal)

e = Employee('Hema', 48, 100, 10000)
e.eatndrink() # Inherited from Person
e.work() # Own method
e.empinfo() # Own method

Inheritance Benefits

Employee inherits Person's methods (eatndrink()) and attributes (name, age) while adding its own features (work(), empinfo(), eno, esal).

IS-A vs HAS-A: When to Use Each

IS-A Relationship

Use when: You want to extend existing functionality with more features.

  • Employee extends Person
  • Dog extends Animal
  • Car extends Vehicle
  • "is a kind of" relationship

HAS-A Relationship

Use when: You just want to use existing functionality without extending.

  • Employee has a Car
  • Person has a Address
  • University has Departments
  • "has a" relationship

Key Insight

In the combined example: Employee class extends Person class functionality (IS-A) but just uses Car class functionality (HAS-A).

Employee IS-A Person (inheritance for extending behavior)

Employee HAS-A Car (composition for using functionality)

Benefits of HAS-A

  • Code reusability without inheritance
  • Looser coupling between classes
  • Easier to test and maintain
  • Flexible - can change implementation easily

Benefits of IS-A

  • Code reusability through inheritance
  • Method overriding for polymorphism
  • Establishes hierarchical relationships
  • Natural modeling of real-world relationships

Best Practices

  • Favor composition (HAS-A) over inheritance (IS-A)
  • Use inheritance only for true "is-a" relationships
  • Keep inheritance hierarchies shallow
