Garbage Collection in Python

The Problem in Old Languages

In languages like C++, programmers are responsible for both creation and destruction of objects.

  • Programmers carefully create objects
  • But often neglect destroying useless objects
  • Memory fills with useless objects
  • Leads to "Out of Memory" errors
  • Application crashes

Python's Solution: Garbage Collector

Python has an assistant running in the background to destroy useless objects.

  • Always running in background
  • Destroys useless objects automatically
  • Reduces memory problems significantly
  • Less chance of "Out of Memory" errors

Main Objective

The main objective of Garbage Collector is to destroy useless objects.

Eligibility for Garbage Collection

If an object does not have any reference variable, then that object is eligible for Garbage Collection.

GC Control Enabling/Disabling Garbage Collector

Python provides the gc module to control garbage collection.

import gc

# Check if GC is enabled
print(gc.isenabled()) # Returns True if GC enabled

# Disable GC explicitly
gc.disable()
print(gc.isenabled())

# Enable GC explicitly
gc.enable()
print(gc.isenabled())
True
False
True
Default Behavior

By default, Garbage Collector is enabled in Python. We can disable it based on our requirements.

Destructor Basic Destructor Example

Destructors are special methods named __del__ that perform cleanup before object destruction.

import time

class Test:
  def __init__(self):
    print("Object Initialization...")

  def __del__(self):
    print("Fulfilling Last Wish and performing clean up activities...")

# Create object
t1 = Test()

# Remove reference (makes object eligible for GC)
t1 = None

# Give GC time to work
time.sleep(5)
print("End of application")

End of application
Important Note

The job of destructor is NOT to destroy the object. Its job is to perform cleanup activities (closing database connections, files, etc.). Once destructor execution completes, the Garbage Collector automatically destroys the object.

Reference Counting When Objects Are Destroyed

An object is only eligible for GC when its reference count reaches zero.

import time

class Test:
  def __init__(self):
    print("Constructor Execution...")

  def __del__(self):
    print("Destructor Execution...")

# Create object with multiple references
t1 = Test()
t2 = t1 # Now 2 references to same object
t3 = t2 # Now 3 references to same object

# Delete first reference (ref count: 3 -> 2)
del t1
time.sleep(2)
print("Object not yet destroyed after deleting t1")

# Delete second reference (ref count: 2 -> 1)
del t2
time.sleep(2)
print("Object not yet destroyed even after deleting t2")

# Delete last reference (ref count: 1 -> 0)
print("I am trying to delete last reference variable...")
del t3
time.sleep(2)
print("End of program")
Reference Changes

After t1 = Test(): 1 reference

After t2 = t1: 2 references

After t3 = t2: 3 references

After del t1: 2 references

After del t2: 1 reference

After del t3: 0 references

Key Rule

If the object does not contain any reference variable then only it is eligible for GC. In other words, if the reference count is zero then the object is eligible for garbage collection.

List Objects Multiple Objects in a List

When objects are stored in a list, they're destroyed when the list is deleted.

import time

class Test:
  def __init__(self):
    print("Constructor Execution...")

  def __del__(self):
    print("Destructor Execution...")

# Create list with multiple Test objects
my_list = [Test(), Test(), Test()]

# Delete the entire list
del my_list

# Give GC time to destroy objects
time.sleep(5)
print("End of application")
Constructor Execution...
Constructor Execution...
Constructor Execution...
Destructor Execution...
Destructor Execution...
Destructor Execution...
End of application
List Reference Behavior

When we create objects inside a list, the list holds references to those objects. When we delete the list (del my_list), all references to the objects are removed, making them eligible for garbage collection.

Finding Reference Count

Using sys.getrefcount()

The sys module provides getrefcount() to find how many references an object has.

import sys

class Test:
  pass

# Create object
t1 = Test()

# Create multiple references to same object
t2 = t1
t3 = t1
t4 = t1

# Check reference count
print(sys.getrefcount(t1))
5
Important Note About getrefcount()

For every object, Python internally maintains one default reference variable called self. Additionally, getrefcount() temporarily creates an extra reference while counting, which is why we see 5 references instead of 4 in the example above.

Python vs C++ Memory Management

C++ (Manual Management)

  • Programmer creates objects
  • Programmer must destroy objects
  • Memory leaks common
  • "Out of Memory" errors frequent
  • More control but more responsibility

Python (Automatic GC)

  • Programmer creates objects
  • Garbage Collector destroys objects
  • Memory leaks rare
  • "Out of Memory" errors rare
  • Less control but less responsibility

Benefits of Garbage Collection

  • Prevents memory leaks
  • Reduces programming errors
  • Improves application stability
  • Simplifies memory management
  • Automatically handles circular references

Destructor Use Cases

  • Closing database connections
  • Closing file handles
  • Releasing network resources
  • Logging object destruction
  • Any cleanup before object deletion

Best Practices

  • Let GC do its job (don't disable unless necessary)
  • Use destructors for cleanup, not business logic
  • Be aware of reference cycles
  • Monitor memory usage in large applications
  • All examples feature Hema for consistency
