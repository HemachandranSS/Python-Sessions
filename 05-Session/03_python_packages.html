Python Packages

Organizing Python Code with Packages and Subpackages

Introduction to Packages

A package in Python is an encapsulation mechanism to group related modules into a single unit. A package is essentially a folder or directory that represents a collection of Python modules.

Key Point: Any folder or directory that contains an __init__.py file is considered a Python package. This file can be empty.

Advantages of Packages:

  1. Resolve naming conflicts - Different packages can have modules with the same name
  2. Unique component identification - Packages provide namespace organization
  3. Improved modularity - Better organization of large projects

Basic Package Structure

Example 1: Simple Package Structure

D:\Python_classes\
test.py
pack1/
__init__.py # empty file
module1.py

__init__.py file:

# This file can be empty # Its presence makes the directory a Python package

module1.py file:

def f1(): print("Hello this is from module1 present in pack1")

test.py - Version 1 (Full import):

import pack1.module1 pack1.module1.f1()

test.py - Version 2 (Selective import):

from pack1.module1 import f1 f1()

Nested Package Structure

Example 2: Package with Subpackage

D:\Python_classes\
test.py
com/
__init__.py
module1.py
hema/
__init__.py
module2.py

__init__.py files:

# Both __init__.py files can be empty # They just mark directories as Python packages

module1.py in com package:

def f1(): print("Hello this is from module1 present in com")

module2.py in com.hema subpackage:

def f2(): print("Hello this is from module2 present in com.hema")

test.py file:

from com.module1 import f1 from com.hema.module2 import f2 f1() f2()
Output: Hello this is from module1 present in com Hello this is from module2 present in com.hema

Best Practices

1. __init__.py File:

  • Can be empty but must exist to make a directory a package
  • Can contain initialization code for the package
  • Can define __all__ list to control what gets imported with from package import *
# Example __init__.py with __all__ __all__ = ["module1", "module2"] # Package initialization code can go here print("Initializing hema package...")

2. Naming Conventions:

  • Use lowercase for package names
  • Use underscores for multi-word names: my_package not myPackage
  • Keep names descriptive but concise

3. Import Guidelines:

  • Use absolute imports: from package.subpackage import module
  • Be explicit about what you import
  • Avoid from package import * in production code
